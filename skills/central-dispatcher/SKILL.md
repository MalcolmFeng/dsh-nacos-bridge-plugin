# 编排与任务流转手册

本手册约定跨工具与多轮任务流转的规范。单工具的用途和参数以该工具的 description 为准；本手册只覆盖工具 description 表达不了的部分。

## 异步任务流转（是否异步，以工具 description 为准）

**不要预设任何命名规律**：某工具是否异步、提交/查询工具分别叫什么名字，都由该工具的 name/description 说明。常见形态如下，但不限于此：

- **提交即完成的同步任务**：调用后直接返回最终结果，无需二次查询。
- **提交 → 拿单号 → 事后查询**：调用"提交类"工具会返回一个单号/taskId；随后用返回单号调用"查询/结果类"工具取终态。
- 通用处理原则：
  1. 先读工具 description，确认它是同步还是异步、返回什么、下一步该调哪个工具。
  2. 若拿到的是"受理中/处理中"而非终态，向用户说明任务已受理并给出单号，建议稍后查询；**不要在同一轮内反复轮询**。
  3. 用户回访时凭单号查询，拿到终态后整合输出最终结果。
  4. 缺失必要信息（如单号）时先向用户澄清，不要臆造。

## 对话型智能体多轮（a2a__<name>__chat）

适用于对话型能力：

- 把用户问题作为 message 发送。
- 若返回 waitingInput=true，说明后端智能体在追问，把追问转达用户，用户补充后再调同一工具补全。
- 同一会话内多次调用会自动保持上下文；连续对话时应基于同一用户诉求延续，不要另起炉灶。

## 多能力编排

同一诉求可能拆成多步、跨工具协作，典型组合：

- **任务型 + 对话型**：先用 A2A 对话确认条件/收集信息，再提交 MCP 任务型工具执行（或反之），最后整合为一份答复。
- **数据 + 结论**：先取数，再结合上下文解释，不要只透传数字。
- 多步编排时逐步执行，每步用上一工具的真实返回驱动下一步；不要臆造中间结果。

## 输出要求

- 始终以统一的助手人格回复；工具结果是中间数据，整合后再输出，不透传原始 JSON。
- 关键字段用自然语言解释其含义。
